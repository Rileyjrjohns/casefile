# Live Jev measurement — October 24, 2026

One live measurement completed 294 Jev questions on the 30 frozen fictional
reference cases, alongside the local demonstration policy. All calls completed;
Jev's final recommendations matched the reference in **23 of 30 cases**. Technical
success is distinct from agreement with the reference policy.

The requested alias was `jev-latest`; every response reported `jev-1.14.0`.
The run started at `2026-10-24T19:44:32.522328+00:00`. Configured rates were USD
0.042 per million input tokens and zero for output. Estimated total provider cost
was **USD 0.010646118**, or **USD 0.0003548706 per represented case** across all
decision purposes. These are configured usage estimates, not a billing receipt.
The run used limits of USD 0.05 and 500,000 tokens, with no retries.

not provider explanations: the typed API does not supply a narrative rationale.

The injection-related recommendation disagreements need investigation before
broadening provider responsibilities. They do not by themselves establish that
Jev followed the injected instructions; detecting an instruction and deciding how
to handle the case are separate questions. No automated final decision was made.

For tool routing, Jev chose transactions before KYC in 23 cases, conflicting with
the fixed reference order. Every benchmark question includes the full evidence
snapshot, even when asking for the next tool. This measures agreement with that
ordering rule, not the quality of an adaptive investigation. The six narrative
model disagreements select `conservative` where the reference selects `primary`.
The priority disagreement is `case-029`, whose declared alert type is an unusual
transaction but whose evidence includes a sanctions match.

## Scope and reproduction

This is a single run on small, correlated synthetic cases whose labels await
independent human review. ECE uses ten bins of selected-outcome probability;
latency is client wall time on the local machine. There are no repeated-run
confidence intervals, real-world fraud outcomes or LLM-provider measurements.
The three newer banking dossiers are separate from this frozen 30-case corpus.
The six earlier successful demo investigations do not establish performance on
these broader questions.

At measurement time, no golden cases, expected labels, runtime routing or provider
prompts were changed to obtain these results. Subsequent versioned application
changes are recorded below. Runtime authorization, source validation, budgets
and the human-review boundary remain independent checks.

## Follow-up through the complete investigation

The same `case-021`, `case-022` and `case-028` evidence was subsequently run through
isolated API intake, the worker, evidence collection, signal extraction and source
retrieval, using the current runtime configuration: live Jev for priority and
recommendation, demo policy for detection and support, deterministic narrative.
Evidence came from the frozen tool snapshots, with no production database writes.

Jev returned `escalate`, `escalate` and `request_information`, respectively.
All three stopped at `AWAITING_REVIEW`, with no human decision. In this workflow,
the recommendation sees the extracted instruction signal, unlike the standalone
benchmark's complete raw-evidence question. The two measurements are distinct;
the original 23/30 benchmark result remains unchanged.

[ADR 018](../adr/0018-recommendation-closure-constraints.md) adds an independent
constraint against model-proposed closure with unresolved concerns or missing
evidence. Regression tests intentionally force `close`, verify the adjusted
recommendation and preserve the original model answer in the trace.
